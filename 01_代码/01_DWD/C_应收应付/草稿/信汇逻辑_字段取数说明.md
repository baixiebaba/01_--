# 信汇逻辑字段取数说明

> 对应脚本：`账龄.sql` 第5段“信汇票据补充数据”  
> 目标表：`dwd.dwd_fi_mr_arap_detail_mi`  
> 参数：`@year_month_day`，格式为 `YYYYMMDD`  
> 文档日期：2026-08-14

## 1. 写入方式

主SAP账龄数据先通过 `INSERT OVERWRITE` 覆盖参数月份，信汇数据随后通过独立的 `INSERT INTO` 追加到同一目标表。按当前执行顺序，同月重跑会先清除当月旧数据，再重新生成信汇数据，不会在正常完整重跑中重复累积。

## 2. 数据来源

| 用途 | 当前Doris表 | 原逻辑来源 | 说明 |
|---|---|---|---|
| 信汇票据月末快照 | `ods.odsmt_fin_bill_view_data` | `ODS.ODSMT_FIN_BILL_VIEW_DATA@FMSLK` | 当前物理表名待数据库确认 |
| 内部公司账户映射 | `ods.odsfima_ztab_9000_acct_maping` | `ZTAB_9000_ACCT_MAPING` | 当前物理表名待数据库确认 |
| 公司、法定总部及SAP系统 | `ods.odsfima_azienda` | `AZIENDA` | `CITTA_LEGALE`转换为`system_src` |
| 科目映射 | `dim.dim_rule_fi_mr_acct_mapping` | 账龄现有规则 | 按科目、系统、有效月份匹配 |
| 客商转对方公司 | `dim.dim_rule_fi_mr_cust2ctp_mapping` | 账龄现有规则 | 优先于信汇原始公司关系 |

## 3. 预处理逻辑

### 3.1 月末快照

```text
DATA_DATE = 参数月份最后一天，格式YYYYMMDD
```

例如参数为 `20260801`，读取 `DATA_DATE='20260831'`。

### 3.2 票据去重

从 `BILL_CODE` 中拆出票据编号、子序号和区间。同一“票据编号 + 区间”内按照子序号倒序排列，只保留 `ROW_NUMBER()=1` 的记录。

### 3.3 应付公司识别

```text
AP_BUKRS = 账户映射表BUKRS
若账户映射未命中，则按CREDIT_CUSTOMER_CODE匹配AZIENDA.SEDE_LEGALE，取最小COD_AZIENDA
```

### 3.4 应收公司识别

```text
若HOLD_CUSTOMER_NAME='青岛海信商业保理有限公司'，AR_BUKRS固定为9002
否则优先按HOLD_CUSTOMER_ACCOUNT匹配账户映射表BUKRS
账户映射未命中时，按RECEIVE_CREDIT_CODE匹配AZIENDA.SEDE_LEGALE，取最小COD_AZIENDA
```

## 4. 过滤和汇总口径

1. 仅保留票据去重后的 `RN=1`。
2. 排除 `BILL_STATUS=9999`。
3. 排除应收公司与应付公司相同的数据；两侧均为空时也排除。
4. 按“应付公司 + 应收公司 + SIGN_DATE”汇总 `BILL_AMOUNT`。
5. 排除汇总金额为0的数据。
6. 仅处理 `dt_month >= '202607'`。
7. 目标组织排除 `9000、9002、9003、9005、9008`。
8. 目标组织必须能够通过 `AZIENDA.CITTA_LEGALE` 映射到六套SAP系统之一：`S600/S700/S800/S900/S610/S810`。

> 当前信汇结果不是逐票据明细，而是“应收公司 + 应付公司 + 签收日期”的汇总明细。

## 5. 应收、应付双边生成规则

| 项目 | 应收方向 | 应付方向 |
|---|---|---|
| 目标组织 | `AR_BUKRS` | `AP_BUKRS` |
| 对方公司原始值 | `AP_BUKRS` | `AR_BUKRS` |
| 科目类型 | `D` | `K` |
| 原始科目 | `1122000095` | `2202000095` |
| 主户编码 | `XH_ + AP_BUKRS` | `XH_ + AR_BUKRS` |
| 主户名称 | `应收账款-信汇` | `应付账款-信汇` |
| 金额符号 | `SUM(BILL_AMOUNT)` | `-SUM(BILL_AMOUNT)` |

当对方公司为空时，主户编码使用 `XH_Z001`。

## 7. 对方公司映射优先级

信汇主户编码先按账龄现有规则匹配：

```text
匹配键 = cust_code + system_src + cust_type_code
```

客商类型转换：

```text
acct_type_code='D' -> cust_type_code='C'
acct_type_code='K' -> cust_type_code='V'
```

映射表有效期：

```text
NVL(valid_fr,'202401') <= dt_month
NVL(valid_to,'999999') >= dt_month
```

同一匹配键有多条有效记录时，优先选择 `valid_fr` 最新的记录。对方公司字段内部优先级为：

```text
cp_company_code_mr非空 -> cp_company_code_mr
否则                 -> cp_company_code
```

最终目标字段优先级为：

```text
客商转对方公司映射结果
-> 未命中时回退信汇原始公司关系：应收取AP_BUKRS，应付取AR_BUKRS
```

## 8. 科目映射逻辑

匹配键：

```text
acct_src_code + system_src
```

有效期：

```text
valid_fr <= dt_month
NVL(valid_to,'999999') >= dt_month
```

同一科目和系统存在多条有效映射时，按照 `valid_fr DESC、valid_to DESC、acct_map_code` 排序取第一条。

## 9. 账龄逻辑

```text
baseline_dt = SIGN_DATE
```

```text
SIGN_DATE为空：aging_days = 1
SIGN_DATE非空：aging_days = 月末关键日 - SIGN_DATE + 1
```

月末关键日由参数月份最后一天生成。起算日当天计入账龄，因此结果加1。
