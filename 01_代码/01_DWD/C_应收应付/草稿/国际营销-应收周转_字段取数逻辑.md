## 1. 文档范围与结论

- 分析对象：`01_代码/01_DWD/C_应收应付/国际营销-应收周转.sql`。
- 分析版本：以当前已保存 SQL 为准；行号均为目标 SQL 的 **1-based 行号**。
- 最终投影：外层 `SELECT z.*`，输出顺序继承内层 `SELECT`，共 **19 个字段**：15 个维度/属性字段、3 个实际当月应收金额字段、1 个加载时间字段。
- 金额处理：最新 SQL 直接输出 A1 金额，**已取消 `/10000` 缩放**；实际计量单位无法由本文件确认。
- 装载目标：本文件只有查询，没有 `CREATE TABLE`、`INSERT` 或 `INSERT OVERWRITE`，因此不存在可由本文件确认的装载目标或装载方式。
- 指标范围：当前只输出实际当月应收余额，没有销售收入、计划值、上月值、同期值、周转率、周转天数或平均应收余额计算。
- 推断标记：标记为 **【推断】** 的内容无法仅凭目标 SQL 和数据字典完全证实，需由业务或源表负责人确认。

## 2. SQL 整体流程

### 2.1 主流程

1. 外层使用 `SELECT z.*` 输出内层派生表全部字段（第 1 行）。
2. 从 `ads.ads_fi_mr_accounts_rec_di` 读取应收事实数据，只保留 `dsource='ACT'`（第 35-38 行）。
3. 按 `A1.grp=A2.grp` 左关联大区/区组维表 `dw.dwsd_im_td_bdr_area_group`（第 39-44 行）。
4. 按 `A1.prdln=A3.prdln` 左关联启用状态的产品维表 `dw.DWFI_IM_TD_PRODUCT_CATEGORY`（第 45-50 行）。

## 5. CASE、默认值与空值处理

### 5.1 大区中文名称

大区 CASE 使用严格的从上到下优先级：

```text
2025-04起指定产品线/01A0特殊区组 → 产品线大区
2025-04前指定产品线             → 产品线大区
空大区的非指定产品线或8002口径   → 欧洲区
其他                             → A2.rgn_zh
```

当 `A3.prdln IS NULL` 时，`A3.prdln NOT IN (...)` 的结果通常为未知值而非 TRUE，因此空产品线记录不一定进入“欧洲区”，可能最终返回 `A2.rgn_zh`。

### 5.2 一级区组中文名称

- `type='8002'`：固定“欧洲海外”。
- 其他：取 A2 维表的 `grp_zh`。
- A2 未匹配：返回 `NULL`，没有“其他”默认值。

### 5.3 客户账期

- A5 映射命中且 `zterm_c` 非空：取 `zterm_c`。
- A5 未命中或 `zterm_c` 为空：固定“其他”。

### 5.4 金额空值

3 个金额均为直接取值，没有 `COALESCE/NVL/IFNULL`：

```text
源金额为 NULL → 输出 NULL
源金额为 0    → 输出 0
```

1. `bus_model` 是业务模式编码还是名称。
2. `sm` 是交易币、本位币还是其他报表币种。
3. `extent` 的业务定义、值域以及编码/名称属性。
4. `custfundcode/custfundname` 是否确实来自 A1；当前通过字段可见范围推断。

6. `end_amt_*_m` 的正式金额单位，以及 `_m` 是否严格表示自然月月末余额。
7. `cod` 是否正式等同 DWD 的 `bcy`；本文依据中文别名“本位币”作映射。
8. ADS 主表 `ads.ads_fi_mr_accounts_rec_di` 的粒度、主键和金额上游计算公式；仓库中未找到其 DDL/加工脚本。
9. A2/A3/A5 的连接键是否由源系统保证唯一。

## 7. 数据质量与实现风险

1. **阻断：外层过滤引用已删除字段**。第 74 行引用“日期”，但最终派生表没有该字段，SQL 当前无法正常执行。
2. **维表关联可能放大金额**。A2/A3/A5 没有按连接键压成唯一记录；一个键对应多条属性时会复制事实行。
3. **无月份输出**。当前 3 个金额按字段名是“本月”值，但最终结果不含 `dt_month`，下游无法仅凭结果区分数据月份。
4. **金额单位不透明**。取消 `/10000` 后恢复为 ADS 源值，但源表单位没有在本文件或当前仓库定义中说明。
5. **K1/K2 为冗余关联**。客户简称已删除，两套客户名称 JOIN 不再参与输出或过滤，可增加不必要的执行开销。
6. **过滤窗口边界**。即使修复“日期”列，第 74 行使用当前月减 24 月且为 `>=`，若含当前月通常覆盖 25 个自然月；没有上界也会保留未来月份。
7. **字符串月份比较**。月份过滤只有在 `month_dt` 固定为 6 位 `YYYYMM` 时才能保证时间顺序正确。
8. **不存在周转指标**。若最终目标仍是应收周转分析，还缺少平均应收余额、周转率/天数公式、年化天数和零分母处理。

## 8. SQL 修复建议（不改变当前 19 列输出）

若希望保留最近月份过滤但不恢复“日期”输出，可把条件下推到 A1：

```sql
SELECT *
FROM ads.ads_fi_mr_accounts_rec_di
WHERE dsource = 'ACT'
  AND month_dt >= DATE_FORMAT(ADD_MONTHS(NOW(), -24), '%Y%m')
```

然后删除外层第 74 行的 `where 日期 >= ...`。这会保持 19 个最终字段不变。该建议尚未应用到 SQL。
