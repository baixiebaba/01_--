# ARPM02 账龄本位币桶的期末汇率换算

本次修改在 `CURRENT_SOURCE` 中把汇率评估标识为空的交易币账龄金额转换为本位币，但存在会改变结果的汇率分支问题：2023 公司没有使用脚本既有的 TCURR 规则，且 BCY 汇率为 0 时不会回退原 BCY。Watch for: **confirmed** 2023 公司的 0—15 桶可能按错误汇率计算；**confirmed** BCY 汇率为 0 会把金额直接变成 0；**likely** 重复且数值不一致的汇率会被静默选取最大值。

**Verdict**: NEEDS_CHANGES

## High-level view

新增逻辑在 `CURRENT_SOURCE` 连接按币种聚合的 `DATI_CAMBIO`，没有复用后段为 2023 公司准备的 `TCURR_RATE`。回退逻辑对 QCY 汇率检查了非零，却只检查 BCY 汇率非空，导致 BCY=0 被当作可用汇率；汇率表重复行则被 `MAX(CAMBIO_FINALE)` 隐式压平，若重复值不一致，结果会依赖最大值而非明确的业务规则。

<details>
<summary>Issues (3)</summary>

1. **2023 汇率来源错误** — 2023 公司的新增 BCY 桶换算仍取 `DATI_CAMBIO`，未使用既有 `TCURR_RATE`；按公司分支改用 TCURR，并在无匹配时回退原 BCY。
2. **零 BCY 汇率未回退** — `BCY_RATE.RATE = 0` 被视为可用并把 0—15 桶算为 0；将 BCY 汇率条件改为非空且非零后回退原 BCY。
3. **冲突汇率静默取最大值** — 同币种不同汇率时 `MAX(CAMBIO_FINALE)` 可能造成系统性偏差；明确唯一汇率规则或对冲突数据阻断/告警。

</details>

<summary>Details</summary>

### 2023 公司绕过 TCURR 汇率分支

**confirmed**：`CONVERSION_RATE`（目标文件第 146—153 行）无论公司取数，均从 `DATI_CAMBIO` 按场景、期间、币种取 `MAX(CAMBIO_FINALE)`；`CURRENT_SOURCE` 第 515—519 行的 QCY/BCY 两个连接也没有公司条件。这样 `COD_AZIENDA='2023'` 且标识为空的记录仍按 `DATI_CAMBIO` 的两段人民币基准汇率换算，而不是后段已有的 `TCURR_RATE`（第 783—800 行）按 `TCURR=本位币、FCURR=交易币` 取 SAP 汇率。结果会与脚本自身对 2023 `CLOSING_RATE_BCY_AMT` 的特殊规则不一致；应让 2023 的 BCY 桶换算走同一 TCURR 口径，并对无匹配汇率回退原 BCY。

### BCY 汇率为零时未回退原 BCY

**confirmed**：0—15 桶的 CASE 条件只要求 `BCY_RATE.RATE IS NOT NULL`（例如第 201—202 行和第 486—487 行），没有排除 `BCY_RATE.RATE = 0`；而表达式随后直接乘以该汇率。非 CNY 本位币且汇率值为 0 时，标识为空的每个 BCY 桶都会被计算为 0，而不是按“汇率缺失/无效时保留原 BCY”回退。BCY 汇率应与 QCY 汇率一样同时要求非空且非零（必要时还要定义负值处理）。

### 重复汇率被静默取最大值

**likely**：`CONVERSION_RATE` 仅按 `COD_VALUTA` 分组并使用 `MAX(CAMBIO_FINALE)`。如果同一场景、期间、币种存在多个不同汇率，这会无提示地选择最大值，可能对全部相关账龄桶造成系统性金额偏差；如果重复行只是完全相同的快照则不会产生差异，但当前 SQL 没有验证这一前提。应按业务唯一键先消除真正重复，或明确有效记录优先级并在重复冲突时阻断/告警，而不是直接取最大值。

</details>
