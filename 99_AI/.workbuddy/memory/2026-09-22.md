## 咨询：Tagetik 对外提供后台表 API 的方式
- 用 tagetik-knowledge MCP 的 tagetik_knowledge_answer 拉取对外集成主题（分类查询 Q1~Q6）。
- 已确认的**产品原生机制**：
  1. REST API Endpoint（系统管理 SA_Endpoint_s.htm）：配置 type=REST API 引用外部 REST 服务，属性 url/restResponseType(JSON|CSV)、认证 authenticationType=N(None)/B(Basic)/O(OAuth2.0，可 JWT)；**用于 Tagetik 调用外部 API，非对外暴露自身表**。
  2. 内置 REST/OpenAPI·OData API 集：Data Model、Job、ETL、MDM、Audit、Comments、Analytical Workspace（见 API/Catalog.htm）；AW 数据抽取 API 明确支持外部系统抽取数据并触发处理（AIH_API_c.htm）。
  3. DB API（SA_DB-API_c.htm）：按 OData v4.0 标准的 RESTful API 执行数据库导入/导出，根端点 `<api root>/admintools/`，需满足条件。
  4. ETL 模块（最成熟可控）：Extraction→Transformation→Loading；加载目标可为外部 Excel/CSV/XML 文件、通用库、Tagetik 自定义表(map_formato_export 等)。Data Target 表：map_easy_output / map_formato_export 系列。
- **关键结论/提醒**：MCP 对"任意应用库后台表直接经 API 读取"返回 INSUFFICIENT/PARTIAL——**没有证据支持"一键把任意后台表暴露为 REST 端点"的通用功能**；产品 API 是预定义 API 集，非对任意表即开即用。务实路径：实时查询→DB 视图+只读账号 或 自封 API 网关；批量同步→ETL 导出文件/外部库。
- 认证安全：生产勿用 None，优先 OAuth2.0/JWT 或 Basic。

## 澄清：「期间长度」在两种场景下的不同含义（重要）
- 用户连续问了两次"期间长度"。必须区分两个**同名不同义**的概念：
  1. **合并场景期间(consolidation scenario period)里的 period length**：系统自动赋给新期间的属性=「前一个参考期间」，用于按期间平均汇率换算、去合并取上一期间。**与 API 拉 AW 表的数据范围无关**（API 用 scenario/period 过滤+Partition 决定）。
  2. **Excel 拉 AW 展示表/矩阵时的「期间长度」**：是**累计计算规则(LUN_* 族)**，以模板筛选的基准期间 n 为参照，决定累计起点。取值：LUN_0(不计算、显示库金额，CPM 默认)、LUN_1(n&n-1 月)、LUN_2(n&n-2 双月)、LUN_3(季)、LUN_6(半年)、LUN_12(年)、LUN_QTD(季初至今)、LUN_STD(半年初至今)、LUN_LYD(有生以来累计)。**此选项会真正影响数据金额**（改变累计起点→改变展示值），非滚动窗口、非列数布局。多维 AW 矩阵仅经 in-Memory Reporting 引擎运行。证据未确认 Excel 插件里该选项的确切点击路径，也未确认是否同时改变列数。
- 来源：`DM_periodo_c.htm`(Period length values)、`REP_DesignForm_c.htm`(多维 AW 矩阵行为)。
