# Implementation Plan

## 已核对的范围与前提

- 执行引擎由用户明确为 **Oracle**；本计划仅允许改动下列六个文件中 `CREATE OR REPLACE PROCEDURE ... ) AS` 之后、变量声明之前的过程头注释，不得改动任何参数、声明、SQL、PL/SQL、普通代码注释、空白格式或业务逻辑。
- 唯一版式基准是 `01_代码/02_DWM/C_应收应付/CPM_SP_M2M_ARP_TOV_M_PHASE2.sql` 的现有过程头；但该基准当前的起始符为 `/**************************************************************************`、且未含“创建日期”，与项目 Oracle 必守规范的 `/**** ... */` 和创建日期要求冲突。实施时采用 **TOV 的栏目顺序、字段措辞和两段历史布局**，并按必守规范将所有实际改动文件的注释边界统一为 `/****` 与 `*/`；创建日期只可采用可信资料中的原始值，不可由文件时间或 Git 提交时间推定。
- 当前工作区已有未提交改动：D2M、AG、BD、TOV 四个目标过程均处于修改状态；这些改动不属于本任务，实施前必须基于执行时的当前文件内容建立基线，不能用 Git HEAD 覆盖或还原。
- 已检查项目根目录及可检索范围：未发现 `README*`、`AGENTS*`、`CONTRIBUTING*`、`.kiro/steering/*`、`package.json` 或 `pom.xml`，因此没有项目定义的构建/测试命令。验证以头部边界和主体不变性比对、`git diff --check`、以及（有可用 Oracle 非生产连接时）数据库编译为准。

## TOV 基准头的统一规格

1. 过程头位于 `) AS` 之后、第一条变量声明之前，使用如下块注释边界；不在头部之外新增业务说明或修改标识：
   ```sql
   /****
   ...
   */
   ```
2. 字段和排序以 TOV 为准，并为满足 Oracle 文件头必守字段补入“创建日期”。固定顺序为：`最后更新时间`、`本次修改`、`上次修改`、`名称`、`功能描述`、`源表`、`目标表`、`创建日期`、`修改历史`。其中“功能描述”统一替换现有的“用途”；TOV 当前的“逻辑文档地址/逻辑文档”“特殊逻辑”“说明”“手工执行”等栏目均不是统一必填栏目，除非其内容可以原样保留且不干扰上述固定顺序，否则不在统一头中新增或改写业务事实。
3. `最后更新时间` 填实施时本地时间，格式 `20261027 HH:MI`；`本次修改`必须为 `ALTER BY 20261027 HH:MI SHIQINGFENG.EX 统一Oracle过程头格式，未修改业务主体。`；`上次修改`只展示紧邻的前一条完整历史记录。`HH:MI` 必须在同一文件的这三处完全一致：`最后更新时间`中的时分、`本次修改`、`修改历史`第一条。
4. `修改历史`置于头部末尾，按时间从近到远排列：第一条为本次格式化记录，随后完整保留该文件既有历史文字（包括缺少时分的原始记录），不得补造既有记录时分、作者或业务说明。头部仅保留“本次修改”和“上次修改”两条摘要，不得将更早记录复制到摘要区。
5. 本任务的改动位置就是过程头本身；头部中的“本次修改”及“修改历史”首条使用同一完整 `ALTER BY 20261027 HH:MI SHIQINGFENG.EX ...` 标识，作为该头部改动的紧邻中文修改标识。不得因本任务在过程业务主体中追加 `-- ALTER ...`，以免违反“仅头部允许改动”。
