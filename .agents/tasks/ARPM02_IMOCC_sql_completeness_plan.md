- 当前目标 SQL 的问题定位：
  1. `TOV_BG_SCOPE` 使用 `${$ANL_D_BG.code}`，并被 `ATS_BG_MAP`、`PCR_BG_MAP` 间接用于前置事业部过滤；这会使 `BG_TURNOVER_NET` 不能覆盖全部有效事业部。
  2. `AZI_SCOPE` 通过 `AW_RUL_DWMCRS_000001` 的 `ZAW_D2M_IN` 规则限制公司，违反本轮移除进数/锁定表限制的要求。
  3. `ARPTOV_RULE` 的批次、有效期、`ARPTOV_FLAG` 判定，以及 ARPM02 的 `ME_AGE_FLAG/MB_AGE_FLAG` 条件当前仍应保留。

## 风险与待确认项

- 参考 TOV 仍登记并使用 `AW_RUL_DWMCRS_000001`，而本轮用户明确要求校验查询删除该表的锁定/进数限制；这是有意保留的“查询 SQL 与装载过程不同”差异，不能为了追随 TOV 文本而恢复该表引用。
- “事业部为空 + 参数事业部”筛选必须建立在负净额已按全量事业部完成之后。实施时应使用独立的实际计算事业部和最终展示事业部，避免先过滤再把结果误标为有效周转。
- 账套或利润中心存在多条有效事业部映射时，必须继续通过 DISTINCT/COUNT 聚合标记冲突，不能直接多表明细 JOIN，否则会放大周转金额；该风险只能通过 SQL 结构检查发现，不能由本轮数据库样例验证确认。
- 当前目标 SQL 与参考 TOV 均在工作区有既有未提交修改；不得使用回滚、重置或格式化参考文件的方式清理状态。最终不提交、不推送。
- 本轮不确认 Oracle 实际执行计划、数据库字段类型兼容性、真实业务金额或 ARPM03 全链路结果；这些属于用户明确要求的后续整体校验。
