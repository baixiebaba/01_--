# 海信开发规范

本规则来自工作区知识库 `98_临时存/kbdata_副本.json` 的“开发规范”必守项，并对当前及后续新会话生效。编写、修改、审查或解释本项目代码时，默认遵循以下要求。

## 引擎与方言

- 先确认实际执行引擎，不得仅凭目录或文件名推断：通常 DWD/DWS 为 Apache Doris，DWM/ADS 为 Oracle 存储过程；跨层场景以实际执行引擎为准。
- Doris 使用 `SET @var`、`DATE_FORMAT`、`INTERVAL n DAY` 等 Doris 语法；Oracle 存储过程使用 `CREATE OR REPLACE PROCEDURE`、`EXECUTE IMMEDIATE`、`NVL`、`SYSDATE` 等 Oracle 语法。不得混用方言。

## 文件头、版本与改动注释（必守）

- **统一文件头样式（Doris 脚本与 Oracle 存储过程）**：使用加宽星号边框的块注释，即 `/*******************************************************************************` 开始、`******************************************************************************/` 结束；块内各信息行使用 `*` 前缀，标题为“脚本说明”或“存储过程说明”，标题下使用 `*-----------------------------------------------------------------------------` 分隔线。
- **Doris 脚本文件头内容**：依次包含最后更新时间、本次修改、上次修改、脚本名称、功能描述、源表、目标表、修改历史；不保留“创建日期”字段。脚本名称使用实际文件名，功能、源表和目标表必须以 SQL 文本或已确认资料为准，无法确认时标注“待确认”。
- **Oracle 存储过程文件头内容**：依次包含最后更新时间、本次修改、上次修改、过程名称、功能描述、源表、目标表、修改历史；不保留“创建日期”字段。过程名称必须与 `CREATE OR REPLACE PROCEDURE` 声明一致，功能、源表和目标表必须以 SQL 文本或已确认资料为准，无法确认时标注“待确认”。
- **统一修改历史规则**：最新版修改记录必须置于最前，“上一版修改”仅保留紧邻的上一版；文件头末尾保留完整“修改历史”清单，按修改时间从近到远排列。新增记录必须精确到时分，格式为 `ALTER BY <YYYYMMDD> <HH:MI> <人>.EX <说明>`；既有历史缺少时分时原样保留，不得伪造时间。仅格式化且未改变代码内容时，不新增伪造业务修改记录；如格式化需要交付，按真实格式调整内容记录。
- 无论 Doris 脚本还是 Oracle 存储过程，任何实际修改都必须在**改动代码所在位置**增加中文说明，并包含修改标识；格式必须与文件头修改记录完全一致：`ALTER BY <YYYYMMDD> <HH:MI> <人>.EX <说明>`。同一次改动的代码位置标识须复用文件头中相同的日期、时间和账号，确保可通过该组合条件检索定位对应代码；如项目正式修改人不是 `LICHENG.EX`，以用户明确指定的账号替换；不得伪造人员、日期或时间。
- 仅格式化且未改变代码内容时，不新增伪造的业务修改记录；如格式化本身需要交付，须依上项记录真实修改说明。

## 分段与普通注释

- 除文件头外，普通代码段、业务逻辑、CTE 用途和字段筛选条件使用连续的 `--` 中文行注释，不使用块注释。
- 不同执行阶段使用分隔线和中文说明，例如目标表装载、第一段覆盖、第二段追加、上线前核对项。
- 关键业务逻辑、CTE 用途、字段筛选条件和新增逻辑均须有紧邻的中文说明。

## SET 与执行顺序

- 运行参数集中放在脚本前部，每个参数先用 `--` 说明，再执行 `SET`。
- 多个语句依赖会话变量时，明确注明必须在同一 session 中按顺序执行。
- 不在业务 SQL 中重复定义同一参数，或通过无意义的单行参数表关联读取参数。

## CTE 与字段格式

- 每个 CTE 上方紧邻一条中文用途注释，说明来源表和处理目的。
- `SELECT` 字段采用逐行排列和逗号前置风格：第一列不加逗号，后续字段行首使用 `,`。
- `FROM`、`JOIN`、`WHERE`、`GROUP BY`、`ORDER BY` 等关键字按统一层级缩进；关键筛选条件单独换行，并在条件上方增加中文行注释。

## D 层建表字段顺序

- D 层（DWD/DWM）建表语句中，存在 `dt_month` 时必须置于字段清单第一列；存在 `load_dt` 时必须置于全部业务字段之后，作为最后一列。
- 新增字段不得破坏上述顺序；调整历史字段时，须同步核对对应 `INSERT` 字段清单列序。

## UNION ALL

- 按查询复杂度选择写法：简单源表映射可将单个 `SELECT` 分支压缩为一行；复杂业务分支按字段逐行展开。
- 简单分支保持 `SELECT ... FROM ... WHERE ...` 一行结构，`UNION ALL` 通常独占一行；复杂分支完整展开字段、别名、`JOIN` 和筛选条件。
- 六套 SAP 系统源表按 S600、S700、S800、S900、S610、S810 的顺序展开，除非业务需求另有规定。

## 大小写规范

- Apache Doris 脚本：SQL 关键字、内置函数和数据类型使用大写；未加引号的库名、表名、字段名、CTE 名和别名使用小写。
- Oracle 脚本：SQL 关键字、内置函数、数据类型以及未加引号的库名、表名、字段名、CTE 名和别名全部使用大写。
- 字符串字面量、注释以及引号或反引号包裹的内容按业务原样保留。

## 修改原则

- 优先保持现有字段顺序、别名、CTE 边界和业务逻辑不变；格式化不得顺带改变过滤条件、连接关系、聚合粒度或字段语义。
- 修改前先对照知识库、项目 SQL/DDL 和用户最新需求；三者不一致时保留差异并明确说明，不静默覆盖。
- 新增逻辑补充中文注释和上线前核对项；涉及业务规则时，同时确认对应配置表及有效期字段。
