# F_APAR_REC 配置化设计说明

## 1. 结论

`F_APAR_REC` 可以配置化，而且建议拆成“规则头表 + 条件明细表”，不要把完整判断写成一个 `condition_sql` 字符串。这样后续新增公司、科目、客商例外时只增加数据，不修改主查询。

规则匹配的核心原则：

- 不再分别调用 `P_FLAG='1'` 和 `P_FLAG='2'`，一次匹配同时输出 `reclass_flag` 与 `reclass_type`。
- `rule_priority` 复刻原函数 `CASE WHEN` 的先后顺序，越小越先命中；`rule_group` 用于审计和按路由查看，不改变全局优先级。
- 不同条件维度之间是 AND；同一维度内可以用 OR 表示 IN，也可以用 AND 表示 NOT IN。
- `valid_fr/valid_to` 取代散落在代码注释中的修改日期，允许按月份切换版本。
- `fact_id` 必须在本次计算范围内唯一，避免配置表关联后金额重复。

## 2. 原函数行为摘要

| 输出类别 | 含义 |
| --- | --- |
| `AR` | 应收 |
| `OR` | 其他应收 |
| `AS` | 预付 |
| `AP` | 应付 |
| `OP` | 其他应付 |
| `AC` | 预收 |
| `CA` | 合同资产 |
| `CL` | 合同负债 |
| `RF` | 应收款项融资 |
| `A9` | 其他流动性资产 |
| `A10` | 长期应收款 |

常规系统的标准逻辑：

- `1122%`：金额大于等于0为 `AR`，小于0重分类为 `CL`。
- `1221%`：金额大于等于0为 `OR`，小于0重分类为 `OP`。
- `1123%`：金额大于等于0为 `AS`，小于0重分类为 `AP`。
- `1124%`：`RF`，不重分类。
- `1460%`：`CA`，不重分类。
- `1466%`：正数 `CA`，负数重分类为 `CL`。
- `2202%`：小于等于0为 `AP`，大于0重分类为 `AS`。
- `2203%`：`AC`，不重分类。
- `2204%`：`CL`，不重分类。
- `2241%`：小于等于0为 `OP`，大于0重分类为 `OR`。

## 3. 必须特别确认的历史行为

1. 旧 `ETL_HI_DATA_APARAGI.sql` 将 `MANDT='680'` 转成了 `600`。因此“原函数的680规则”和“旧ETL实际走600规则”是两个口径，配置表不应偷偷合并，建议在事实预处理层显式选择。
2. 600、680、700、800B、810、880 的未知科目在原函数中通常返回 `P_FLAG='1' -> N`、类别为空；800/900总部类分支的未知科目返回空值。配置模板保留了这一差异。
3. `P_YEARMONTH` 当前没有参与函数判断；配置表增加有效期后，新增规则必须维护生效月份。
4. 原函数的 `NOT LIKE '9008'`、`NOT LIKE '9003'` 没有 `%`，实际是“不等于9008/9003”，而不是排除前缀。配置初始化按原实际语义处理；若业务要排除前缀，需单独改配置。
5. `P_DMBTR IS NULL` 时，所有金额正负判断均不成立。模板不会把 NULL 自动当作0，避免改变原函数边界行为。
6. 旧ETL同时计算 `DMBTR_REC` 和 `DMBTR_REC_M`，前者按公司/客商/科目净额，后者增加利润中心粒度。两者要分别匹配配置，不能直接复用同一个金额结果。

## 4. 文件说明

- `dim_rule_fi_mr_ar_reclass-建表语句.sql`：创建规则头表和条件明细表。
- `dim_rule_fi_mr_ar_reclass-初始化数据.sql`：初始化当前 `F_APAR_REC` 规则。
- `dim_rule_fi_mr_ar_reclass-匹配模板.sql`：提供 Doris CTE 匹配模板，一次输出标识、类别和命中规则。

## 5. 推荐接入位置

当前 `CPM_SP_D2M_ARP_M.sql` 只读取 DWD 汇总数据，并不直接调用 `F_APAR_REC`。如果后续还需要重分类结果，推荐在 DWD 明细或生成 DWD 汇总的窄事实阶段计算，并将以下字段带到汇总：

- `reclass_flag`
- `reclass_type`
- `matched_rule_id`
- `matched_rule_code`

如果只在 DWM 的最终聚合后计算，会丢失客商、科目和金额净额的原始上下文。
