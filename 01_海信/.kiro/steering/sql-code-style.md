# SQL代码风格

后续编写或修改本项目 SQL，默认遵循以下规范：

## 文件头与分段

- 文件头必须使用 `/* ... */` 块注释，并在块内使用 `-- ============================================================================` 分隔线。
- 除文件头外，普通代码段、业务逻辑、CTE 用途和字段筛选条件均使用连续的 `--` 行注释，不使用块注释。
- 文件头只保留版本/修改记录和目标表信息，修改记录最新版本放在最上面。
- 不同执行阶段使用分隔线和中文说明，例如目标表装载、第一段覆盖、第二段追加、上线前核对项。
- 关键业务逻辑、CTE用途、字段筛选条件使用中文行注释说明。

## SET与执行顺序

- 运行参数集中放在脚本前部，每个参数先用 `--` 说明，再执行 `SET`。
- 如果多个语句依赖会话变量，应明确注明必须在同一 session 中按顺序执行。
- 不在业务 SQL 中重复定义同一参数或通过无意义的单行参数表关联读取参数。

## CTE与字段格式

- 每个 CTE 上方紧邻一条中文用途注释，说明来源表和处理目的。
- `SELECT` 字段采用逐行排列。
- 采用逗号前置风格：第一列不加逗号，后续字段行首使用 `,`。
- `FROM`、`JOIN`、`WHERE`、`GROUP BY`、`ORDER BY` 等关键字按统一层级缩进。
- 关键筛选条件单独换行，并在条件上方增加中文行注释。

## D层建表字段顺序

- D层（DWD/DWM）建表语句中，存在 `dt_month` 字段时必须将其放在字段清单第一列。
- D层建表语句中，存在 `load_dt` 字段时必须将其放在所有业务字段之后，作为字段清单最后一列。
- 新增字段时不得破坏以上顺序；需要调整历史字段时，应同步核对对应 INSERT 字段清单的列序。

## UNION ALL

- `UNION ALL` 的写法按查询复杂度区分：简单源表映射可将一个 `SELECT` 分支压缩为一行；复杂业务分支则按字段逐行展开。
- 简单分支保持 `SELECT ... FROM ... WHERE ...` 一行结构，`UNION ALL` 通常独占一行，便于快速浏览六套 SAP 来源。
- 复杂分支完整展开字段、别名、JOIN 和筛选条件，不使用不透明的简写。
- 六套 SAP 系统源表按 S600、S700、S800、S900、S610、S810 的顺序展开，除非业务要求另行调整。
- 不为了统一形式而把简单 UNION ALL 过度展开，也不为了减少行数而压缩复杂业务分支。

## 大小写规范

- Apache Doris 脚本（通常为 DWD）：SQL 关键字、内置函数和数据类型使用大写；未加引号的库名、表名、字段名、CTE 名和别名使用小写。
- Oracle 脚本（通常为 DWM）：SQL 关键字、内置函数、数据类型以及未加引号的库名、表名、字段名、CTE 名和别名全部使用大写。
- 字符串字面量、注释及引号或反引号包裹的内容按业务原样保留，不因格式化修改大小写。
- 脚本目录仅用于默认判断；存在跨层或跨引擎场景时，以实际执行引擎确定大小写规范。

## 修改原则

- 优先保持现有字段顺序、别名、CTE边界和业务逻辑不变。
- 格式化时不得顺带改变过滤条件、连接关系、聚合粒度或字段语义。
- 新增逻辑应补充对应的中文注释和上线前核对项。
